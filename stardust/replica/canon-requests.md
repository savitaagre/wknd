# Canon change requests

Archetype prototypes NEVER edit `stardust/prototypes/canon.css` or
`stardust/prototypes/canon.js`. When an archetype's gate shows the shared layer is
wrong for its page (chrome drift, a token or base rule that does not hold, a
missing shared utility), append ONE line below and keep any page-level
compensation in `<slug>.css` until the canon owner back-ports the change and
re-gates every approved archetype (`us-en-html` at 1440 + 360 first).

See `stardust/prototypes/CANON.md` for what each layer owns.

Entry format (one line per request, newest last):

```
- [<archetype slug>] <selector/rule> — <change> — evidence: <gate dir / measure line>
```

Example (illustrative only — not a real request):
`- [us-en-adventures-html] .header-bar padding-top — live 40px on this template vs canon 50px — evidence: stardust/replica/gates/us-en-adventures-html-1440/chrome-parity-iter1.txt "header-bar padding-top 50 → 40"`
